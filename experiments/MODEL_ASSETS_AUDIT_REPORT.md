監査スクリプトは `experiments/audit_training_assets.py`、機械可読結果は `dev/uploaded-model-audit.json`。
この監査はCSVとPythonソース、保存された評価結果を読むだけで、joblibをロード・実行しない。

ソースの19特徴量に結果・払戻6列は含まれない。モデル学習はtrainのみ、確率補正と見送りルールの選択はvalidate、報告評価はtestを使っている。

ただし、CSVに各特徴量の取得時刻・集計の締切時刻がないため、勝率などが当時利用可能な値だったことまでは証明できない。
ZIP内の学習コードとモデルバイナリのハッシュは残したが、このコードがこのバイナリを生成したことも未確認。
これはソースとデータ構造の監査であり、「将来情報が完全に混入していない」と断定するものではない。

## 回収率に関する判断

| 保存済みテスト評価 | レース数 | 的中率 | 投資 | 払戻 | 回収率 |
|---|---:|---:|---:|---:|---:|
| 全レース・上位3点各100円 | 6,998 | 20.73% | 2,099,400円 | 1,627,680円 | 77.53% |
| 見送りルール適用後・上位3点各100円 | 376 | 32.71% | 112,800円 | 86,400円 | 76.60% |

保存された選択後バックテストCSVから投資・払戻・的中数を再集計し、JSONの376レース・123的中・回収率76.60%と一致した。
見送り後は的中率が上がったが、回収率は0.935ポイント下がっている。購入レース集合が異なるため、因果効果や有意差の主張はしない。

確率補正後のBrier scoreも1着・2着・3着すべてわずかに悪化していた。差は小さく、一般に補正が無効という意味ではないが、この結果から補正の改善を主張できない。
また、同じvalidate期間を確率補正の学習と見送り条件の選択に使っている。testへの直接のラベル漏洩とは異なるが、検証期間の成績は楽観的になり得る。

**添付モデルの見送り条件や確率補正を、回収率改善が確認できた変更として採用しない。**
既存テストは既に結果を見ているため、今後の変更で改善したとしても新しい未使用テストの代わりにはしない。

## 次の学習の分離方針

元CSVは変更しない。再学習を実施するときは別の学習用データと別の出力先を用意する。
過去の再現確認ではvalidateを日付単位で二つに分けられる。

| 用途 | 期間 | レース数 |
|---|---|---:|
| 確率補正の学習 | 2025-01-01〜2025-01-22 | 3,611 |
| 見送り条件の選択 | 2025-01-23〜2025-02-13 | 3,251 |

この分割は再現実験用の候補であり、今回再学習やモデル交換を実施してはいない。
本当の採否は候補を固定した後の、未使用の後続期間で判断する。条件選択に使った成績と採否用の成績は分ける。

## 直近成績の集計処理も作成

`experiments/recent_player_features.py` に、登録番号をキーにした直近30日/90日の集計を実装した。
対象日より前の日だけを使い、同じ日の結果は時間が早い場合でも使わない保守的な仕様。
全体・コース別・場別・場×コース別の出走数、1/2/3着内率、正常着順平均、通常ST平均を返す。
失格などの出走は着順平均から外し、勝率の分母には残す。レース本番のFとLは通常STから分離する。これは展示Fとは別の入力。
欠損は0と置換せずnull、少数サンプルと日付のカバー不足を明示する。

公式履歴393,551出走（修復期間388,014出走＋追加6日5,537出走）で実行した。
元のgzipのSHA-256は公式修復監査の `normalized_rows_sha256` と一致。
前日2026-10-07の出走者から選んだ846件の「登録番号・場・コース」の組を、2026-10-08時点で集計した。
これは特徴量のカバー診断のサンプルであり、2026-10-08のレースへの予想ではない。
前日出走者を選んでいるため、各グループに最低1出走あることは当然であり、汎用の結合率と解釈しない。
すべての組について直近30/90日の必要日付をカバーした。

| 10出走以上のサンプル組数 / 846組 | 30日 | 90日 |
|---|---:|---:|
| 選手全体 | 799 | 844 |
| 選手×コース | 22 | 506 |
| 選手×場 | 60 | 137 |
| 選手×場×コース | 1 | 4 |

したがって、最初の学習候補は「選手全体・コース別」。場×コースの率をそのまま強い入力にするのは避け、出走数を含めた縮約・欠損処理を検証する。
10出走は今回のカバー診断用の区切りであり、予測の信頼性を保証する基準ではない。
学習CSVへの登録番号の結合、将来の締切前予想への登録番号の保存、再学習と未使用期間の評価は未実施。
現在の収集レコードの `input_state` は展示・水面情報で、登録番号自体を含まないため、次の学習用収集では時点付きの選手識別情報も必要。
集計処理を作ったことと回収率改善は区別する。

監査4件＋直近成績4件、合計8件のテストを通過。当日/未来結果の排除、30/90日の境界、F/Lの分離、重複拒否、未登録選手の欠損を確認した。
カバー診断は `dev/recent-player-coverage-audit.json` に保存。

検証順は「監査（完了）→直近成績の集計処理（完了）→登録番号を含む学習用収集・結合と再学習→展示Fの将来比較→オッズ下落の分離診断」。
収集済みの古い予想、投資額、履歴、元モデル、元CSV、本番リポジトリは今回変更していない。

## 再実行

```sh
python experiments/audit_training_assets.py /path/to/kyotei-ai-v8.zip /path/to/boatrace_training.csv --out /tmp/uploaded-model-audit.json
python -m unittest discover -s experiments -p test_audit_training_assets.py -v
python -m unittest discover -s experiments -p test_recent_player_features.py -v
python experiments/recent_player_features.py --official-history dev/racer-starts-official.csv.gz --expected-sha 6dad8730b20f43e11c960ae43c9c1c50450058748cd0566878a15057bdd96847 --daily-dir /tmp/decoded-prospective-source --as-of 20261008 --out /tmp/recent-player-coverage-audit.json
```

監査は標準ライブラリだけで動く。時系列重複、キー重複、不正な着順などの構造異常では非ゼロ終了する。
回収率未改善や特徴量の取得時刻未確認はJSONの判断・制約として残し、データ破損とは区別する。
直近成績カバー診断のdaily-dirには、既存 `dev/aptitude-prospective-source/20261002.json.gz`〜`20261007.json.gz` をJSONとして展開したものを置く。
