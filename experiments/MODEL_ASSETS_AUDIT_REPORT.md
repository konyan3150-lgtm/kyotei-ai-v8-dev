これはソースとデータ構造の監査であり、「将来情報が完全に混入していない」と断定するものではない。

## 回収率に関する判断

| 保存済みテスト評価 | レース数 | 的中率 | 投資 | 払戻 | 回収率 |
|---|---:|---:|---:|---:|---:|
| 全レース・上位3点各100円 | 6,998 | 20.73% | 2,099,400円 | 1,627,680円 | 77.53% |
| 見送りルール適用後・上位3点各100円 | 376 | 32.71% | 112,800円 | 86,400円 | 76.60% |

保存された選択後バックテストCSVから投資・払戻・的中数を再集計し、JSONの376レース・123的中・回収率76.60%と一致した。
見送り後は的中率が上がったが、回収率は0.935ポイント下がっている。購入レース集合が異なるため、因果効果や有意差の主張はしない。

確率補正後のBrier scoreも1着・2着・3着すべてわずかに悪化していた。差は小さく、一般に補正が無効という意味ではないが、この結果から補正の改善を主張できない。
また、同じvalidate期間を確率補正の学習と見送り条件の選択に使っている。testへの直接のラベル漏洩とは異なるが、検証期間の成績は楽観的になり得る。

**添付モデルの見送り条件や確率補正を、回収率改善が確認できた変更として採用しない。**
既存テストは既に結果を見ているため、今後の変更で改善したとしても新しい未使用テストの代わりにはしない。

過去の再現確認ではvalidateを日付単位で二つに分けられる。

| 用途 | 期間 | レース数 |
|---|---|---:|
| 確率補正の学習 | 2025-01-01〜2025-01-22 | 3,611 |
| 見送り条件の選択 | 2025-01-23〜2025-02-13 | 3,251 |

この分割は再現実験用の候補であり、今回再学習やモデル交換を実施してはいない。
本当の採否は候補を固定した後の、未使用の後続期間で判断する。条件選択に使った成績と採否用の成績は分ける。

## 次の検証の準備状況

開発版mainの `d4a3f678f4c1c4ff0830a84fb84c5830a22398d7` にある監査・収集レポートも照合した。
数値は収集レポート更新時刻 **2026-10-08 23:34:54 JST** のスナップショット。

1. **選手の直近成績**：添付CSVには登録番号がなく、選手を推測して結合できない。
   一方、開発版の公式履歴には登録番号・実際の進入コース・場があり、2026-10-07まで1,829,014出走を集計済み。
   `dev/aptitude-prospective-source/20261007.json.gz` の863出走でも登録番号とコースを確認した。
   直近30日/90日の特徴量はこの日付付き公式履歴から作れる。対象日より前の日だけ集計し、予想時のコースには実際の結果コースを流用しない。
   最初に登録番号・場・レースで学習データとの結合率を検証し、欠損や少数サンプルを表示する。
   大きな総出走数はデータ量であり、特徴量の有効性や添付学習CSVとの結合成功を証明するものではない。
2. **展示F**：既存比較の記録691件は、非負ST揃い211件・負STあり345件・欠測/変換不能135件。
   負STは欠測と既に別集計だが、比較の購入条件では除外されている。
   展示Fを独立した入力として比較する次の候補は、開始時刻と扱いを固定して将来の締切前記録だけ保存する。
   過去の終了レースに新しい予想を追記しない。添付CSVのST_AVGと本番レースのF回数は展示STの代用品にしない。
3. **オッズ下落**：完全な締切前オッズと結果がある423レースを既存レポートで確認。
   保存済みEV候補の推定回収率334.14%に対して実現回収率91.94%だったが、この差からオッズ下落を断定できない。
   確率の過大評価・オッズ下落・少数的中のばらつきが混在するため、的中組合せの `公式払戻÷100÷保存オッズ` を別集計する必要がある。
   これは当たり組合せだけの診断。負け組合せの最終オッズは払戻から復元できず、全120通りのオッズ下落の推定に使わない。

検証順は「監査（今回完了）→登録番号で直近成績を結合する検証→展示Fの将来比較→オッズ下落の分離診断」。
収集済みの古い予想、投資額、履歴、元モデル、元CSV、本番リポジトリは今回変更していない。

## 再実行

```sh
python experiments/audit_training_assets.py /path/to/kyotei-ai-v8.zip /path/to/boatrace_training.csv --out /tmp/uploaded-model-audit.json
python -m unittest discover -s experiments -p test_audit_training_assets.py -v
```

監査は標準ライブラリだけで動く。時系列重複、キー重複、不正な着順などの構造異常では非ゼロ終了する。
回収率未改善や特徴量の取得時刻未確認はJSONの判断・制約として残し、データ破損とは区別する。
