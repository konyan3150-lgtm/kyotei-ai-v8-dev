# 登録番号と直近成績の締切前保存

2026-10-09。開発版の修復済み収集ジョブに、将来の学習に使う `learning_inputs` を追加。

出走表の登録番号と予測処理の選手入力を照合し、6艇の一意な登録番号を保存する。欠損・矛盾は推測せず理由を記録する。
直近30日/90日の全体・コース別・場別・場×コース別の成績、出走数、欠損、少数サンプル情報を保存する。
進入コースは締切前の展示で観測できたものだけを使う。未観測時はnullで、艇番や結果の実際のコースから補わない。

履歴は必ず対象日の前日まで。修復済み公式CSVのハッシュと、追加日のB/K識別情報・出走数を公式監査と照合する。
生成した一時データのハッシュ、前日までの履歴時点、公式入力の識別情報を収集レコードに残す。
一時データの読み取り・日付・照合が不良の場合も、既存の予想収集は継続し、学習入力側に利用不可を記録する。

予想処理・買い目・金額の計算にこの入力はまだ使わない。終了・取消済みレコードには追記せず、過去レコードも補完しない。
締切前に入力が変わった場合は旧スナップショットを改訂履歴として保持する。保存時刻だけが変わった場合は改訂しない。
本番リポジトリには変更していない。

## 確認済み

- 公式履歴393,551出走から、2026-10-08時点の特徴量を生成。1,645選手、30/90日すべての日付をカバー。
- 実履歴の特徴量を使った6艇の保存テスト：登録番号・未知のコースの欠損・ハッシュ照合を確認。
- Python：対象日の排除、30/90日境界、F/Lの分離、重複拒否、直接集計との一致。
- JavaScript：登録番号の矛盾拒否、締切後拒否、日付・履歴ハッシュ不一致拒否、元入力の非変更。
- 改訂：新しい学習入力の保存、時刻だけの変更の抑制、終了レコードの不変性。
- 既存の確率補正・入力検証・展示比較・改訂・収集サイクルのテストも実施。

1,645選手は直近窓を作れる日付付き公式履歴にいる選手数で、全期間の適性DBの1,866選手とは対象が異なる。

## 未確認と次の工程

最初の実レースでの保存は、反映後の締切前収集で確認する。深夜に終了レースを使って新しい保存実績を作らない。
添付の古い学習CSVには登録番号がなく、過去の学習データの結合は引き続き未確認。
今後は保存入力と公式結果をレース・艇・登録番号で結合し、学習/確率補正/条件選択/未使用テストを分離して新モデルを検証する。
この変更だけでは回収率改善を証明しない。
